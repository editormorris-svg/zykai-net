智安雲科平台

教育機構需要的不是六個AI工具，而是一個可治理的AI環境。

規劃中的ZYK架構把日常AI應用、獲批准的校本知識、評估服務、治理控制、模型選擇及系統整合連在一起。底層模型可以隨技術演進而更換，而機構仍保留對身份、政策、數據及教育工作流程的控制。

使用者體驗

六個面向日常工作的專注介面。

ZYK Chat · 智聊

私有多模型教育對話，按角色提供存取、學科模式、獲批准知識來源及機構自訂控制。

ZYK Create · 智創

面向教育用途的受治理圖像、影片及媒體創作；在適用情況下加入覆核及AI生成內容標示流程。

ZYK Analyze · 智析

在學校受控環境中進行OCR、文件分析、寫作回饋、資料擷取及題目生成等工作流程。

ZYK Voice · 智聲

發音練習、語音、有聲讀物及語言學習流程；涉及敏感能力時，須受明確政策及適當同意機制約束。

ZYK Code · 智碼

為Python、JavaScript、C++及其他經機構批准的課程語言提供配合課程的編程支援。

ZYK Agent · 智助

為招生、輔導、圖書館、IT服務台、人力資源及財務等界線清晰的機構角色規劃受限助手。

保留的延伸概念

較早期方案中仍值得保留的能力，不會因為架構升級而消失。

班級與團隊工作空間

規劃共享班級資料夾、教師團隊空間及按角色存取的協作環境，讓AI工作流程可以圍繞真實班級與部門組織。

家長入口與溝通流程

未來可探索家長可見的說明、同意、AI素養資源及適當的學習／使用資訊，但不應把家長入口表述為已完成產品。

SIS／MIS整合

除LMS、SSO及API外，若機構需要，可進一步探索學生資訊系統、管理資訊系統及更深層名冊／考試系統整合。

即時翻譯

Voice路線中保留即時翻譯概念，實際可用語言、延遲、準確度及教育適用性需要獨立驗證。

受同意控制的聲音複製

較早期方案包含聲音複製構想。任何實施都應屬高風險、明確同意、可撤回、用途受限的能力，而不是預設開放功能。

相似度／抄襲輔助

Analyze可保留相似度與學術誠信輔助工作流程，但只能作證據提示與教師覆核，不應把AI結果宣稱為權威抄襲判定。

兩種不同的控制職能

Control管理人與政策；Gateway管理獲批准模型的路由。

ZYK Control · 治理控制面

Control是規劃中的行政層，管理使用者、角色、可使用能力、配額、審計、同意、保留、內容控制、審批流程及營運可視性。

了解ZYK Control →

AI Gateway · 模型服務面

Gateway是規劃中的技術路由層，位於已批准的使用體驗之後，按任務、數據政策、批准模型狀態、容量及效能規則選擇或限制模型端點。

了解AI Gateway →

兩者的分工很重要：Control回答「誰可以在甚麼機構規則下做甚麼」；Gateway回答「哪一個獲批准的模型端點可以處理這項已獲授權的要求」。兩者都不能取代實際承載或連接模型的基礎設施層。

基礎設施與整合

讓學校使用體驗保持穩定，同時容許底層技術演進。

模型可遷移性

目標是避免每次模型更新都要重建整套學校體驗。模型及服務技術可以演進，而身份、政策、知識及工作流程保持相對穩定。

身份、LMS及API

可按項目範圍透過角色權限、SSO、名冊、LMS、API、資料庫及在適合情況下的SIS／MIS整合，把獲批准的AI流程連接至既有機構系統。

持續運維

監察、備份、更新、效能管理、生命周期規劃及支援，令平台成為持續的機構服務，而非一次性的伺服器採購。
