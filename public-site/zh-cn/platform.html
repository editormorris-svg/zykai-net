智安云科平台

面向教育机构的AI环境，而不只是六个AI工具。

拟议中的智安云科架构把用户应用、获批校本知识、评估服务、治理控制、模型选择和学校系统集成在一起。底层模型可以持续变化，但学校仍可保持对身份、政策、数据与教育工作流的管理。

用户应用

六类面向日常教学与运营的AI体验。

ZYK Chat · 智聊

私有多模型教育对话，支持角色权限、学科模式、获批知识源以及学校定义的使用规则。

ZYK Create · 智创

面向教育场景的图像、视频和媒体创作，并可按需要加入审核与AI生成内容标识流程。

ZYK Analyze · 智析

在学校可控环境中开展OCR、文档分析、写作反馈、信息提取和题目生成等工作流。

ZYK Voice · 智声

支持发音练习、语音生成、有声读物和语言学习；涉及敏感能力时需纳入明确政策与授权。

ZYK Code · 智码

面向Python、JavaScript、C++等学校批准课程语言的编程辅助。

ZYK Agent · 智助

为招生、升学辅导、图书馆、IT服务台、人力资源和财务等明确岗位规划边界清晰的智能助手。

保留的延伸概念

早期方案中仍有价值的能力继续保留，但不会被包装成已经完成的产品。

班级与团队工作空间

规划共享班级文件夹、教师团队空间和基于角色权限的协作环境，让AI工作流围绕真实班级与部门组织，而不是停留在个人账号层面。

家长入口与沟通流程

未来可探索面向家长的说明、同意管理、AI素养资源以及适当的学习或使用信息；在完成验证前，不应把家长入口表述为已上线产品。

SIS／MIS集成

除LMS、SSO和API外，机构还可能需要更深入的学生信息系统、管理信息系统、名册或考试系统集成，具体取决于项目范围。

实时翻译

Voice方向保留实时翻译概念。实际支持语言、延迟、准确度以及教育场景适用性需要独立验证。

受同意控制的声音克隆

早期方案包含声音克隆构想。任何实施都应按高风险能力处理：明确同意、可撤回、用途受限，并受机构规则控制，而不是默认开放。

相似度／抄袭辅助

Analyze可保留相似度和学术诚信辅助工作流，但输出应作为教师复核的证据提示，而不能被宣传为权威抄袭判定。

两种不同的控制职能

Control管理机构规则，Gateway管理模型路由。

ZYK Control · 治理控制面

拟议中的机构管理层，重点管理“谁可以在什么规则下做什么”：用户、角色、功能权限、配额、审计、同意状态、数据保留、内容控制、审批和运维可视性。

AI Gateway · 模型服务面

拟议中的技术路由层，在请求已经获得授权后，根据任务、数据政策、获批模型状态、可用容量和性能规则选择或限制模型端点。

了解AI Gateway →

两者职责不同：Control回答“谁能做什么、需要遵守什么机构规则”；Gateway回答“这项已获授权的请求可以由哪个获批模型提供服务”。它们都不能替代实际承载模型的基础设施。

基础设施与集成

底层技术可以演进，学校的使用体验和治理体系不必推倒重来。

模型可迁移性

目标是不让学校围绕每一次模型更新重新建设系统。模型和推理技术可以变化，而身份、政策、知识与工作流保持相对稳定。

身份、LMS与API

可根据项目范围连接角色权限、SSO、班级名册、LMS、API、数据库，并在适合时连接SIS／MIS，使获批AI工作流进入现有学校系统。

持续运维

监控、备份、更新、性能管理、生命周期规划和支持服务，使平台成为持续的机构能力，而不是一次性的服务器采购。
